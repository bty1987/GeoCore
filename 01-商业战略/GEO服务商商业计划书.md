# GEO（生成式引擎优化）服务商商业计划书

> 版本：v1.0 | 日期：2026-08
> 定位：技术驱动的 AI 搜索可见性优化服务商（先服务后产品，最终 SaaS 化）
> 核心信条：**卖"可验证的工作过程与数据"，不卖"保证排名"的承诺**

---

## 0. 执行摘要

- **做什么**：为企业客户提供在国内六大 AI 平台（豆包、元宝、DeepSeek、Kimi、通义、文心）及海外平台（ChatGPT、Perplexity、Google AIO、Gemini、Claude）的**品牌可见性诊断 → 内容优化 → 持续监测 → 效果归因**的全链路服务。
- **技术壁垒**：自建**多平台监测引擎**（API + 浏览器自动化双通道）+ **引用解析归因引擎** + **内容生产管线**，形成数据资产与效率优势。
- **商业模式**：服务费（月费制）打底 + 监测 SaaS 订阅 + 效果对赌奖金（可选、谨慎）。
- **启动资金**：约 ¥15–25 万（3 人团队 6 个月 runway + 基础设施）。
- **盈亏平衡**：4–5 个中型客户（月费 ¥1.5–3 万档）。

### 3.2 模块一：监测引擎（核心竞争力所在）

**职责**：定时向各 AI 平台发送查询、捕获完整回答与引用来源。

#### 3.2.1 查询集管理
每个客户维护四类查询词（初始 30–50 条，持续扩充）：

| 类型 | 示例 | 目的 |
|---|---|---|
| 品牌词 | "XX 是什么" / "XX 靠谱吗" | 品牌认知层 |
| 品类词 | "最好的 XX 工具是哪家" | 竞争推荐层（价值最高）|
| 对比词 | "XX vs 竞品A" / "XX 和竞品B 哪个好" | 决策层 |
| 场景词 | "我想解决YY问题有什么推荐" | 长尾场景层 |

查询集生成流程：客户访谈关键词 → LLM 扩展（模拟真实用户问法变体 ×10）→ 人工筛除歧义 → 入库。

#### 3.2.2 采集双通道设计

**通道 A：官方 API（海外平台，合规稳定）**

| 平台 | 接入方式 | 单次成本估算 |
|---|---|---|
| ChatGPT | OpenAI API（开启 web search 工具） | ~$0.02–0.05/次 |
| Perplexity | Sonar API（自带引用，解析最简单）| ~$0.01–0.03/次 |
| Gemini | Google AI API（ grounding 开启后返回引用）| ~$0.01–0.03/次 |
| Claude | Anthropic API（web search tool） | ~$0.02–0.05/次 |

**通道 B：浏览器自动化（国内平台，技术难点所在）**

国内平台大多不开放对话 API，需要 Playwright 驱动真实浏览器会话：

```python
# 采集 Worker 伪代码（每平台一个适配器，统一接口）
class DomesticAIAdapter(ABC):
    async def ask(self, query: str) -> AIResponse:
        """返回：回答全文 + 引用来源列表 + 页面快照"""
        # 1. 从会话池取一个已登录/已过验证的浏览器上下文
        # 2. 模拟人类输入节奏（逐字输入 + 随机停顿 800-3000ms）
        # 3. 等待回答完成（流式DOM监听，超时120s）
        # 4. 解析回答区 + 引用角标，提取来源标题/URL/锚文本
        # 5. 全页截图 + DOM快照存证（对象存储，供报告引用）
        # 6. 会话健康度检查，异常则销毁重建
```

**反爬对抗要点（决定通道 B 成败）**：
- **账号池**：每平台储备 5–20 个账号，轮换使用，单账号日查询 ≤ 15 次（模拟真人）
- **指纹管理**：每浏览器上下文绑定独立 Canvas/WebGL/UA 指纹（playwright-stealth 或商业指纹浏览器）
- **代理 IP**：住宅代理池，IP 与账号固定绑定（避免异地跳变触发风控）
- **行为仿真**：随机滚动、随机鼠标轨迹、会话间随机间隔 3–10 分钟
- **降级策略**：验证码 → 先尝试自动求解（打码服务）→ 失败转人工处理队列；连续失败自动熔断该账号 24h
- **频率纪律**：宁可慢不可封。全平台扫描任务错峰分布在 7×24h 执行

> ⚠️ **合规提示**：浏览器自动化采集各平台 AUgc，需注意平台服务协议风险。建议：(1) 控制频率模拟真实用户；(2) 不存储平台非公开数据，仅保留与客户品牌相关的回答快照；(3) 对外报告仅引用结论与来源链接。此为行业通行做法，但需持续关注平台政策变化，必要时收缩为"人工 + 半自动"。

#### 3.2.3 调度设计
- Redis 队列 + Celery/APScheduler，任务粒度：`客户 × 平台 × 查询`
- 默认频率：品牌词每周 1 轮，品类词/对比词每两周 1 轮（控制成本与账号消耗）
- 每轮结束自动 diff 上一轮结果，变化项标记进入人工复核队列

### 3.3 模块二：引用解析与归因引擎

**职责**：把原始回答变成结构化指标。

```
原始回答 → ① 来源提取 → ② 实体识别 → ③ 倾向分类 → ④ 指标计算 → ⑤ 入库
```

1. **来源提取**：正则 + DOM 解析提取引用 URL/域名/标题；国内平台部分引用无 URL（如豆包引抖音视频），降级为"标题+平台"识别
2. **实体识别**：LLM 执行 NER，识别回答中提到的所有品牌/产品名及其位置（第几位推荐、出现在哪个章节）
3. **倾向分类**：三级标签——正面推荐 / 中性提及 / 负面评价/风险描述
4. **核心指标（我们的产品语言）**：

| 指标 | 定义 |
|---|---|
| 提及率 | 被提及查询数 / 总查询数 |
| 引用率 | 被列为来源的查询数 / 总查询数（更高质量）|
| 推荐位次 | 品类词回答中的推荐排序（中位数）|
| Share of Model | 我方提及次数 / (我方+所有竞品提及总次数) |
| 倾向净值 | 正面提及 − 负面提及 |
| 平台覆盖数 | 在几个平台有稳定提及（0–10）|

5. **归因关联**：引用来源 URL 反查我们历史的分发内容库（公众号文章 ID、知乎回答 ID 等），形成 **"哪篇内容 → 被哪个平台引用 → 贡献多少提及"** 的证据链，这是向客户证明价值的关键。

### 3.4 模块三：内容生产管线（服务交付的效率引擎）

```
品牌事实库 (Brand Fact Sheet)
    │  ← 客户提供 + 访谈补全 + 每月更新（单一事实源，全渠道口径统一）
    ▼
平台内容模板库
    │  ← 每平台一套：公众号问答体 / 知乎决策体 / 头条测评体 /
    │     抖音60秒口播脚本 / 百科词条结构 / CSDN技术教程体
    ▼
LLM 批量草稿生成 (结构化 prompt，强制引用事实库数据，禁止编造)
    ▼
人工审核编辑（专业编辑岗，防幻觉、注入平台调性）
    ▼
分发执行（账号矩阵发布 + 互动维护）
    ▼
回链登记 → 进入归因引擎（闭环）
```

**要点**：
- 事实库是数据资产：客户停服后带走的是文档，带不走的是我们沉淀的行业模板库与查询集数据
- 每篇内容有唯一追踪 ID（自定义短链 / 特定措辞标记），便于归因引擎识别"这条引用来自我们的内容"

### 3.5 模块四：报告与客户门户
- 周报（自动生成 PDF/网页）：指标趋势 + 本周变化明细 + 证据快照链接
- 月报（人工 + 自动结合）：归因分析 + 下月优化计划
- 门户功能（MVP 后期）：客户自助查看看板、调整查询集、导出报告

| 难点 | 风险等级 | 应对 |

## 5. 合规与诚信红线（写在公司章程里）

1. **不承诺"保证排名/保证收录"**——技术上不可控，承诺即欺诈风险。话术统一为"基于数据的持续优化与透明监测"。
2. **不刷虚假提及、不伪造用户口碑**——Google 明确打击，国内平台风控同样会识别，且会污染客户品牌。
3. **采集行为克制**：模拟真实用户频率，不获取平台非公开数据。
4. **合同条款**：明确交付物清单（监测报告/内容篇数/分发渠道数）、监测口径、数据停止条款——这也是对自身保护。
5. 客户数据隔离与保密（多租户权限）。

> 定位话术参考："我们是 AI 时代的 Search 数据公司 + 内容工程公司，不是玄学排名贩子。"

- 基础设施与账号储备：¥2–4 万
- 杂项（注册、法务合同模板、营销）：¥1–3 万

**盈亏平衡**：月固定成本约 ¥4–5 万（含低薪）≈ 4 个 L2+L3 客户（¥12k 均价）
**12 个月目标**：10–15 个付费客户，MRR ¥15–25 万，验证后启动 SaaS 化融资或利润化经营。
