## 一、这份文档是什么

一份 **B2B 销售赋能印刷手册**（最终交付形态：A4 PDF，约 8–12 页）。委托人是一支「GEO（AI 搜索优化）+ 企业系统定制开发」的技术服务团队；把手册发给自己的**渠道合伙人**——人资行业背景、手里有大量企业客户、**完全不懂技术**。手册要同时完成三件事：

1. **教**：让合伙人听懂「为什么 GEO 和系统开发是一件事」（获客 + 接单闭环）
2. **武装**：给他现成的商机信号对照表、话术库、微信转发文案——照着听、照着说
3. **可转发**：其中有一节是直接复制给终端客户看的介绍词

对应源稿（内容一字不改，只做排版设计）：`/Users/Admin/.zcode/workspace/default/合伙人转述手册-开发能力与产品线-模板.md`

**重要取舍**：源稿开头「模板使用说明」引用块是内部元信息，**设计稿不渲染**；从主标题开始。全文所有【】占位符（含【X–X 万】等）**原样保留**并做成醒目的占位样式（参考类名 `.ph`：金色虚线下划线），不得编造数字填充。

## 二、读者画像与使用场景

- 读者：中国中小企业服务圈的渠道合伙人，35–55 岁，微信重度用户，非技术背景，对「ERP/CRM/进销存」只有模糊概念
- 场景①：拿到手册先花 15 分钟通读，判断「这事我能不能干」
- 场景②：见客户前 2 分钟翻第四节信号对照表「热身」
- 场景③：把 5.2 微信话术、第八节客户介绍词**直接复制转发**
- 潜台词：读者怕露怯、怕被技术词羞辱。设计的任务是**降低理解门槛、给足开口的底气**——这是赋能材料，要让他读完觉得「这事我能干」，而不是「好专业但我记不住」

## 五、输出格式与技术约束（三版统一，不得偏离）

- **单文件纯 HTML/CSS**，无 JS、无外网资源、无图片（本文档是排印型内容，Phase 3.5 判定：图片非内容必需；不点名展示第三方产品 logo，品牌词只作正文文本）
- **A4 纵向连续多页文档**（不是 1920 deck）：`@page { size: A4; margin: 8mm 0 16mm; }`，屏显容器宽 ≤1000px 居中；**不要自己做页脚页码**（导出脚本通过 Chromium headerFooter 统一注入运行页脚）
- 打印分页：`@media print` 内对表格行、话术卡、链条图 `break-inside: avoid`；大节起始用 `break-before: page` 自行裁量，杜绝孤行标题
- **可读性硬底线**：正文 ≥14px、注释/标签 ≥12px、正文对比度 ≥4.5:1——任何风格温度不豁免
- 字体只用本机可用栈：衬线 `"Songti SC","Noto Serif SC",STSong,serif`；黑体 `-apple-system,"PingFang SC","Hiragino Sans GB","Microsoft YaHei",sans-serif`；等宽 `ui-monospace,"SF Mono",Menlo,monospace`。可自选权重/字距，不得引入需下载的字体
- 反 slop：禁 emoji 当图标、禁紫渐变、禁「圆角卡+左彩色 border accent」默认组合（若所选风格 DNA 本身含描边/撞色，按风格执行，但排版纪律照守）
- HTML 顶部注释写明：assumptions、所选逻辑与参照、以及一句话「**form 来自内容的哪里**」（答不出=在套模板，回去重答）
