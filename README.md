## 这是什么

GeoCore 是 GEO（AI 搜索可见性）业务的**唯一资料主场**：商业战略、渠道合作、客户交付模板、监测引擎代码、设计产线、归档情报，全部资产一处存放、跨设备长期维护。它承载的不是单个产品，而是**两条互哺的业务线**——主线做 GEO 服务（让客户在豆包/元宝/DeepSeek 等 AI 回答里被提及、被推荐），拓展线接住由此长出来的系统定制开发生意。

**它解决的真实问题：**

- 客户在 AI 回答里"搜不到、不被提及、不被推荐"，传统 SEO 接不了这一层——**GEO 主线**解决（L1 诊断 → L2 监测 → L3 优化执行 → L4 战略托管）；
- GEO 客户每月看数据，天然暴露"线索没人跟、库存靠 Excel、审批靠签字"——**定制开发拓展线**接住；
- 周报靠人手拼、效果证据链不完整——**监测引擎 + 六件工具链**解决（引擎未上线前手填 CSV 同 schema，链路照跑）。

**仓库边界（卖点，也是底线）**：私有商业仓库——含定价、渠道条款与客户进展，**保持私有**；对外文档不留 AI 痕迹、不虚构案例；空针=自建试验田，对外不得包装成案例。

## 双线业务定位与市场卡位

| 线 | 内容 | 逻辑 |
|---|---|---|
| **① GEO 产品线（主线）** | AI 可见性服务：L1 诊断 → L2 监测 → L3 优化执行 → L4 战略托管 | 让客户在豆包/元宝/DeepSeek 等 AI 回答里被提及、被推荐 |
| **② 系统开发拓展线（粮草）** | 进销存 / CRM / 财务对接 / OA / 行业 ERP / 定制开发 | 通过 GEO 客户的长期维护与合伙人、客户推荐，获取系统开发机会 |

两线关系一句话：**GEO 把客户带到门口，系统把推荐来的生意接住。** 系统客户的获客焦虑又反哺 GEO。渠道合伙人双线佣金：GEO 首年 15%–25%，开发项目首单 10%–15%、续约 5%。

| 市场参照 | 量级 | 相对位置 |

## 业务架构（每周闭环）

```text
空针 40 词 × 3 平台（豆包 / 腾讯元宝 / DeepSeek）
 ▼
geo-engine-v0 监测引擎（限频调度 · 截图存证 · CSV 台账）
 ├─▶ weekly_report.py  周报草稿 ── --json ─▶ portal.html 客户只读门户
 ├─▶ quickcheck.py     快查报告（获客钩子，客户视角）
 └─▶ attribution.py    归因核对（发布台账 × 监测引用）
        ▲                            │
        │ 发布登记                    │ 引用回血验证
 内容量产工作台（事实库 + 六平台模板 + 起草 prompt）◀── 周报"需优化词清单"
```

引擎未上线期间，手动填写基线记录表（14 列 schema 与引擎产出同源）即可跑通全链路：监测/填表 → 周报（+门户数据）→ 未提及词喂内容工作台出内容 → 发布登记归因台账 → 归因核对。

## 技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 监测引擎 | Python 3 + Playwright | 适配器抽象（豆包先行）、限频调度（单账号日查 ≤15）、全页截图存证 |
| 数据工具链 | Python 标准库（CSV/JSON） | 周报/快查/归因三脚本，引擎产出与手工填写同一 schema，可无缝切换 |
| Web 前端 | 纯 HTML/JS，单文件 SPA，零后端零构建 | localStorage 演示存储；配置文件与页面分离，调价只改配置 |
| PDF 产线 | Node + Playwright（HTML→PDF） | 咨询报告体模板家族，六个项目共用导出脚本 |
| 渲染质检 | Python + pypdfium2 | 逐页 PNG，供人工/评审验收 |

## 快速开始 / 常用操作

### geo-web 本地预览
```bash
cd 05-引擎/geo-web && python3 -m http.server 8777
# 演示版   http://127.0.0.1:8777/index.html
# 客户询价 http://127.0.0.1:8777/quotation.html
# 渠道助手 http://127.0.0.1:8777/quotation-dealer.html（禁公网部署，口令见 quotation-dealer.config.js）
```

### 周报 / 快查 / 归因（引擎工具链）
```bash
cd 05-引擎/geo-engine-v0
python weekly_report.py --this-week 本周台账.csv [--last-week 上周台账.csv]   # 周报草稿，--json 出门户数据
python quickcheck.py --this-week 台账_快查_YYMMDD.csv [--industry 房产家装]  # 客户视角快查报告（获客钩子）
python attribution.py --book 发布台账.csv --ledger output/ledger_doubao_*.csv # 发布×引用归因核对
```

### 给客户/合伙人出新 PDF（三步）
1. 改 `03-客户交付模板/` 对应模板里的【】占位符
2. 改 `06-设计工程/<项目>/design-demos/` 里选定的 HTML（内容同步）
3. 导出：
```bash
cd 06-设计工程/GEO客户启动书/scripts
node export_pdf.js ../design-demos/<源html>.html "../<输出>.pdf" "<页脚文档名>"
# 合伙人转述手册项目同理，需指定依赖：
NODE_PATH="$PWD/../GEO客户启动书/scripts/node_modules" node export_pdf.js
```

### PDF 渲染质检（逐页 PNG）
```bash
python3 06-设计工程/render_pages.py "<某.pdf>"   # 依赖：pip install pypdfium2
```

### 环境依赖（一次性）
- node + playwright（`06-设计工程/GEO客户启动书/scripts` 下 `npm i playwright && npx playwright install chromium`）
- python3 + pypdfium2（渲染质检）

## 常见问题（FAQ）

**Q：「空针数据」是什么？**
自建试验田的品牌名——非外部客户，对外不得包装成案例；geo-web 与演示材料的品牌位用它，对外口径只用"试验田"。

**Q：引擎自动化还没跑通，周报怎么出？**
基线记录表手动填写（14 列 schema 与引擎产出同源），`weekly_report.py` 照常统计出稿，`--json` 出门户数据；引擎上线后无缝切自动采集。

**Q：渠道版报价助手为什么禁止公网部署？**
它含底价/毛利/提成测算。护栏是三层：不随公网部署、主机白名单软校验（仅本地/白名单域名可开）、口令帘（只是防随手点开，不是安全机制）。底价口径只存在于仓库与渠道私发件中。

**Q：监测会不会把账号弄封？**
纪律先于功能：单账号日查询 ≤15、查询间随机等待 3–10 分钟、全任务错峰、账号/指纹/代理一一绑定——宁可慢，不可封。

**Q：密钥和运行数据放哪？**
`config.yaml` 与 `output/` 已 gitignore 不入库，仓库只提交 `config.example.yaml`；交付模板不带客户名，按客户复制时另命名。

## 使用边界与维护规则

- **红线**：本仓库含商业定价与渠道条款，**保持私有**；对外文档不留 AI 痕迹、不虚构案例
- **归档**：过时的谈判底稿、一次性竞品情报、被新版替代的文档 → 进 `99-归档/`，文件名带年月
- **命名**：正式交付物带版本与日期（如 `xxx-v2咨询报告体.pdf`）；模板不带客户名，按客户复制时另命名
- **提交**：改完即 commit，一句话说明改了什么；推送 `git push`（凭证在系统钥匙串）
- **部署**：geo-web 公网只上传客户版白名单文件（`index.html`/`quotation.html`/`quotation-config.js`），渠道版两件绝不公网部署
