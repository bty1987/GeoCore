# 内容量产工作台 v0（P1-3）

> 一句话：**让每篇内容都成为 AI 愿意引用的语料**——不是发帖数，是"权威、一致、可验证"。
> 组成：`事实库-模板.csv` ＋ 六平台内容模板（本文件下半部）＋ 生成规范与 prompt（下节）。
> v0 = 纯模板＋规则，零开发；跑顺后接内容量产（v1 再考虑半自动生成）。

---

## 一、核心规则（CITE，违反＝白写）

1. **强制引用事实库**：每篇内容必须引用事实库条目（fact_id），成稿里每个关键事实都要能回溯到 F 编号。没有事实支撑的话不写——AI 不引用空话，人也别写。
2. **三类词埋点**：每篇至少含 1 个品牌词、1 个品类词（如"装修 ERP 系统"）、需要时带地域词。埋点自然，不堆砌。
3. **一致性 > 数量**：同一事实在所有平台口径完全一致（公司定位、数字、名称），互相打架的语料会拉低全部平台的信任度。改口径必须先改事实库再动内容。
4. **权威源优先**：能挂在官网/公众号认证号/知乎实名账号的内容，优先级高于小号群发。一个认证源 > 十个马甲。
5. **留痕**：发布后登记归因台账（见 P2-6），两周后用 attribution.py 对照监测数据看"被引用了没"。

## 二、生成流程（人工＋AI 协作，单篇 ≤30 分钟）

```
选题（来自周报"需优化提问词清单"）→ 挑 fact_id（2–4 条）→ 复制下方对应平台模板
→ 把模板连同事实贴给 AI 让它起草（prompt 见下）→ 人工核对：事实一致？埋点自然？
→ 发布到对应平台 → 登记 P2-6 归因台账
```

**起草 prompt（复制即用，替换【】）：**

```
你是为【品牌名】写【平台名】内容的运营。严格遵守：
1. 只使用我提供的事实，不得编造任何数据、案例、资质；事实之间不得互相矛盾。
2. 每个关键事实后标注 [F编号] 供我校验，我校验通过后我会让你去掉标注出终稿。
3. 自然埋入：品牌词【品牌名】、品类词【品类词】、地域词【地域词，可无】。
4. 按【平台名】的结构模板组织，字数【按模板】。
以下是可用事实：
[粘贴 fact_id 对应的 content 行]
选题：【本周需优化的提问词或方向】
```

## 三、六平台内容模板

### 1. 公众号（元宝 + 微信搜一搜的语料源，权重最高）

- 结构：标题（含品类词）→ 开头 100 字直接给结论 → 正文 3 段（问题场景 / 方法 / 事实佐证）→ 结尾 FAQ 3 问 → 公司一句话介绍（固定口径）
- 字数 1200–1800；配图 2–3 张（截图证据最佳）
- 关键：**FAQ 段用客户的问法原话**（来自问法矩阵），这是被 AI 抽取引用概率最高的段落

### 2. 知乎（DeepSeek / Kimi 高权重语料源）

- 结构：用提问词当问题 → 实名号回答 → 先给直接答案（3 行内）→ 展开论据（每条带 [F]）→ 结尾"利益相关"声明（诚实=加分）
- 字数 800–1500；**不用营销腔**，知乎语料的权威度来自克制
- 关键：老问题下补充回答 > 提新问题；有赞同票的历史回答定期更新

### 3. 官网（全平台的权威源底座）

- 结构：产品页 / 案例页 / 常见问题页三件套；每页含品牌词+品类词+地域词各 ≥1 次
- 关键：**事实库里的每个 F 编号都必须能在官网找到对应页面**——官网是引用链的终点，AI 引用了公众号但官网查无此事，信任度反噬
- FAQ 页直接按问法矩阵组织（一问一页或一问一段）

### 4. 百家号（百度系 / 文心一言语料源）

- 结构：新闻稿体——标题含品类词 → 导语（何时何地何事）→ 正文事实段 → 企业简介（固定口径）
- 字数 600–1000；不写观点只写事实，百家号适合"动态发布"（新功能/新案例/数据更新）

### 5. 小红书（消费决策场景，C 端获客）

- 结构：真实场景笔记——痛点首图标题 → 个人经历体（300 字）→ 干货清单（带 [F]）→ 评论区自问自答埋问法
- 字数 500–800；**禁功效词/绝对化承诺**；企业号+个人号配合，个人号讲体验、企业号讲事实

### 6. 抖音口播（豆包/头条生态语料源）

- 结构：3 秒钩子（客户问法原话）→ 30 秒讲一个事实 → 结尾一句固定介绍；60–90 秒
- 关键：**文案先写后拍**，字幕逐字=口播稿；单条只讲一个 F，讲透
- 每周 1–2 条即可，配合图文不能停（AI 对视频语料的引用依赖字幕文本）

---

## 四、每周节奏（接周报生成器）

1. 周五跑 `weekly_report.py` → 拿"需优化提问词清单"（就是下周的选题库）
2. 每个未提及词 → 配 2–4 条 fact_id → 产出 2–3 篇（覆盖 2 个平台）
3. 发布 → 登记归因台账 → 下下周对照 `attribution.py` 看引用回血

**一页判断标准**：这篇内容发出去 30 天后，客户问 AI 那个问题时，它有没有可能被翻牌？不可能的，别发。
